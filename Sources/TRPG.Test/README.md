# TRPG.Test — 실시간 HTML 대시보드

서버 상태와 부하 테스트 결과를 브라우저에서 확인합니다. 기본 대상은 Debug에서 로컬 127.0.0.1:60000, Release에서 VM 168.107.37.255:60000입니다. 대시보드는 테스트 PC의 루프백 주소에서만 열립니다.

## 실행

서버를 먼저 실행하고 Windows PowerShell에서 다음을 실행합니다.

```powershell
dotnet run --project "D:\Devs\TRPG.Server\Sources\TRPG.Test\TRPG.Test.csproj" -c Release
```

브라우저가 자동으로 열립니다. 열리지 않으면 콘솔의 `HTML 대시보드: http://127.0.0.1:...` 주소를 직접 여세요. 이 명령은 빌드를 포함합니다. 개발 중 자동 빌드·VM 연결·실제 부하 실행은 하지 않습니다.

- 화면에서 인원 1~999명과 부하 시간을 선택하고 **부하 시작**을 누릅니다. 프로그램을 켜는 것만으로는 부하를 보내지 않습니다.
- **부하 중단**은 가상 클라이언트만 정리하며 채팅 서버를 종료하지 않습니다.
- 테스트가 끝나도 감시와 그래프는 유지됩니다. 대시보드 프로그램 종료는 콘솔에서 Ctrl+C입니다.
- `--clients 100 --seconds 30`은 HTML 입력값을 미리 지정합니다. 즉시 테스트를 시작하는 옵션이 아닙니다.
- 로컬 대상은 `-c Debug`, 고정 접속 시나리오는 `--mode fixed --rate 1`을 사용합니다.
- 테스트 도구는 ASP.NET Core 로컬 호스트를 사용합니다. .NET 9 SDK가 설치된 개발 PC에서 실행하며, VM 서버에는 ASP.NET Core를 추가 설치할 필요가 없습니다.

## Debug와 운영 DB

- **Debug 서버는 DB 연결·조회·저장을 하지 않습니다.** DB 환경 변수도 필요 없습니다. 채팅 중계와 성능 지표는 그대로 동작합니다.
- **Release 서버는 기존 Oracle DB 환경 변수로 접속하고 채팅을 저장합니다.** 테스트 도구의 빌드 구성과 서버 자체의 DB 활성 설정은 별개입니다. 실제 서버의 활성 여부가 대시보드에 표시됩니다.
- 운영 서버가 실제 실행된 뒤 정상 종료되면 `TRPG_APP.CHAT_MESSAGES`의 기록 전체를 삭제하도록 요청합니다. 테이블·계정·인덱스·자동 번호는 유지합니다.
- Ctrl+C, systemd의 SIGINT/SIGTERM 종료 경로를 처리합니다. 정상 종료 시 별도의 취소 토큰으로 최대 20초 후 DB 작업 취소를 요청합니다. 오류·제한 시간 초과 시 기록이 남을 수 있음을 서버 로그에 표시합니다.
- SIGKILL, VM 강제 종료·삭제, 전원·네트워크 장애에서는 종료 코드를 실행하거나 DB에 도달할 수 없어 삭제를 보장하지 않습니다. OCI 콘솔 중지라도 강제 중지인지 정상 OS 종료인지에 따라 다릅니다.
- DB에 기존 등록한 3일 간격 전체 삭제 예약은 그대로 유지합니다.

새 서버 코드를 다시 publish·업로드·서비스 재시작해야 VM에도 반영됩니다. 운영 서버를 재시작할 때에도 정상 종료 경로가 실행되어 기존 채팅 기록이 삭제됩니다.

## 0.5초 감시

서버 표본 생성, SSH/로컬 파일 읽기, 브라우저 조회의 목표 주기는 모두 500ms입니다. 네트워크 지연과 OS 스케줄링이 있으므로 세 단계가 정확히 동시에 실행되거나 지연 없이 표시되는 것을 보장하지는 않습니다. 표본 시각은 KST로 표시합니다.

- **실행 중**: 서버가 실행 중이라고 기록한 지표가 2초 이내에 갱신되고 있습니다.
- **정상 종료 상태**: 현재 읽을 수 있는 파일에 서버가 정상 종료 상태를 남겼습니다.
- **상태 확인 불가**: 갱신이 끊기거나 수집 연결에 문제가 있습니다. 강제 종료와 통신 장애를 단정해서 구분하지 않습니다.
- 서버 재시작을 감지하면 새 세션 지표로 전환하고 감시를 이어갑니다. 부하 중 서버가 재시작되면 해당 테스트 결과는 오류로 표시합니다.
- 구버전 서버 지표는 오류로 표시하므로 최신 서버를 먼저 배포하세요.

서버는 실행 파일 폴더의 `server-metrics.json`을 임시 파일에서 교체합니다. 비밀번호·채팅 내용은 포함하지 않습니다.

- 로컬 기본 경로: Sources/TRPG.Server/bin/Debug/net9.0/server-metrics.json. 다른 출력 폴더는 `--server-metrics-file`로 지정합니다.
- VM 경로: /home/ubuntu/trpg-server/server-metrics.json. SSH 사용자 ubuntu, 기본 키 D:\Docs\us2d-server-main\ssh-key-2026-04-01.key입니다. 다른 키는 `--ssh-key`로 지정합니다.
- 기존 OpenSSH와 known_hosts 검증을 사용하며, 인증 확인을 우회하거나 공개 측정 포트를 추가하지 않습니다. 새 호스트 확인이나 키 암호 입력이 필요하면 일반 SSH 접속을 먼저 직접 완료하세요.
- 서버 실행 계정은 배포 폴더에 지표 파일을 쓸 수 있어야 합니다. 파일 기록 실패는 서버 로그에 표시합니다.

## 화면과 측정 범위

| 지표 | 정의 |
| --- | --- |
| 서버 사양 | OS가 제공하는 논리 프로세서 수, RAM, OS, 프로세스 아키텍처. OCI 상품의 OCPU 수를 추정해서 표시하지 않음 |
| 실행 상태 | 지표 갱신 여부, 정상 종료 표시, PID, 실행 시간, 스레드 수 |
| CPU | 서버 프로세스는 사용 가능한 코어 전체 기준 0~100%, 호스트 전체 CPU는 별도 표시 |
| 메모리 | 호스트 실제 사용량과 서버 프로세스 작업 집합. Windows 로컬·Linux VM 모두 지원 |
| 네트워크 | 활성 비루프백 NIC 전체 RX/TX. DB·SSH 등 다른 통신도 포함하며 OCI 청구량과 동일하지 않음 |
| 연결·수신 큐 | 서버 연결 수와 처리 대기 수. 테스트 접속 수와 서버 전체 접속 수는 구분 |
| DB 저장 | 활성 여부, 완료·실패 누계, 실패율, 평균·최대 지연. 연결 풀 대기부터 INSERT 종료까지 |
| 접속 지연·성공률 | TCP 시작부터 입장 응답까지 성공한 시도의 평균/p50/p95/p99 및 초기·재접속 전체 성공률 |
| 송신·중계 | 부하 구간 평균 송신률·중계 수신률과, 0.5초 화면 관측 구간의 중계량 그래프 |
| 전달 지연 | 테스트 프로세스의 단조 시계로 송신 직전부터 상대 수신까지 관측한 누계 p50/p95/p99 |
| 누락·중복 | 마지막 고정 구성 검증 구간의 예상 전달 대비 미수신·중복률 |

그래프는 브라우저에서 최근 240개 관측 값(약 2분)을 유지합니다. 서버 지표는 수집기에서 최근 최대 3,600개 표본(목표 주기 기준 약 30분)을 유지합니다. 새 값이 없으면 CPU·큐 등은 빈 구간으로 표시합니다. 사양과 누계 결과는 마지막 관측값입니다. p50/p95/p99는 1ms 버킷의 상한이며 10초 초과는 별도 표시합니다.

DB 지연 그래프는 인접 표본 사이에 완료된 저장의 평균입니다. 표에는 서버 프로세스 시작 이후 누계를 표시합니다. DB를 사용하지 않는 Debug에서는 해당 값이 비활성으로 표시됩니다. 수신 큐·CPU 등의 순간 최대는 표본 사이에 놓칠 수 있습니다.

## 무작위 부하 (기본)

- 서버 정원은 1,001명, 테스트 동시 슬롯은 선택한 1~999개입니다. 재접속 대기 중에는 실제 동시 접속 수가 감소합니다.
- 초기 접속을 기본 50ms 간격으로 분산합니다. 999명은 준비에 약 50초가 추가되며, 초기 준비 중에는 채팅을 보내지 않습니다.
- 준비 후 각 슬롯이 500~1000ms 간격으로 메시지를 보냅니다.
- 본문은 ASCII 식별자와 채움 문자로 구성하며 전체 UTF-8 크기가 8~16B입니다. FlatBuffers·TCP/IP 크기는 별도입니다.
- 10~30초 접속 후 종료하고 1~5초 기다려 재접속합니다.
- 추적 한도는 clients × 2 × seconds ≤ 100000입니다. 999명은 최대 50초이며 HTML 화면에서 인원에 맞는 시간 상한을 안내합니다.
- 부하 후 기본 5초간 수신 대기, 고정 구성 검증 메시지 3개 전송, 다시 5초 대기가 추가됩니다.

누락·중복률은 마지막 고정 구성 검증 구간에만 적용됩니다. 무작위 구간 전체의 전달을 보장하지 않습니다. 1명 테스트 또는 검증 시 수신자가 없으면 해당 지표는 측정 불가입니다. 미수신은 대기 종료까지 도착하지 않은 전달이며 영구적인 네트워크 손실로 단정하지 않습니다.

## 고정 모드와 판정

`--mode fixed --rate 1 --chars 20`은 고정 구성으로 방 전체 초당 1개, 한글 20자 + 추적 식별자를 보냅니다. 무작위 모드의 8~16B 조건과 다릅니다. rate 0은 접속 유지 테스트입니다.

테스트 완료 시 클라이언트 오류·고정 구성 검증 실패·관측 구간 DB 실패·지표 중단·서버 재시작을 종합해 화면에 표시합니다. 성능 목표 충족을 자동 인증하는 판정은 아닙니다. 실행 프로그램은 정상 대시보드 종료 시 0, 잘못된 옵션은 2로 종료하며 개별 부하 결과는 화면과 콘솔에서 확인합니다.

실제 VM 테스트는 서버를 최신 코드로 재배포한 후 수행하세요. Release의 건별 DB 저장은 병목이 될 수 있습니다. 수신 큐가 계속 증가하면 서버가 부하를 감당하지 못하는 상태일 수 있습니다. 테스트 PC 자체의 CPU·네트워크 병목도 결과에 포함됩니다.
