# TRPG.Test

실제 FlatBuffers 접속·채팅 패킷으로 부하를 만들고, 클라이언트 관측과 서버 측 표본을 함께 출력합니다. Debug는 로컬, Release는 VM 168.107.37.255:60000이 기본 대상입니다. 서버는 별도로 실행해야 합니다.

## 실행과 인원 선택

Windows PowerShell에서 실행합니다. 인원을 지정하지 않으면 실행 화면에서 1~999 사이의 숫자를 입력받습니다. --help는 선택 화면이나 연결 없이 도움말만 표시합니다.

```powershell
dotnet run --project "D:\Devs\TRPG.Server\Sources\TRPG.Test\TRPG.Test.csproj" -c Release
```

명령으로 인원을 지정할 수도 있습니다.

```powershell
dotnet run --project "D:\Devs\TRPG.Server\Sources\TRPG.Test\TRPG.Test.csproj" -c Release -- --clients 100 --seconds 30
```

위 명령은 빌드를 포함합니다. 개발 과정에서 자동 빌드 또는 실제 부하 실행은 하지 않습니다. VM에 최신 서버를 재배포해야 서버 측 지표도 수집됩니다. 100 → 300 → 500 → 999명 순으로 부하와 지연을 비교하는 편이 좋습니다.

## 무작위 모드 (기본)

- 서버 정원 1,001명, 테스트 슬롯은 사용자가 선택한 1~999개입니다. 재접속 대기 중에는 실제 동시 접속자가 줄어듭니다.
- 초기 접속은 50ms 간격으로 분산합니다. 999명은 준비에 약 50초가 추가됩니다. 초기 준비 중에는 채팅을 보내지 않습니다.
- 준비 완료 후 기본 30초 동안 각 슬롯이 500~1000ms 간격으로 전송합니다.
- 본문은 8자리 ASCII 추적 번호와 채움 문자로 구성하며 UTF-8 본문 전체가 정확히 8~16B입니다. FlatBuffers·TCP/IP 크기는 별도입니다.
- 접속 유지 10~30초, 퇴장 후 재접속 대기 1~5초를 무작위로 선택합니다.
- 추적 메모리 제한은 clients × 2 × seconds ≤ 100000입니다. 999명은 최대 50초를 지정할 수 있습니다.
- 999명 모두 접속 중인 경우 평균 약 1,332개/초의 입력과 약 133만 건/초의 중계를 목표로 합니다. 재접속과 송신 지연이 있으면 실제 부하는 감소합니다.

무작위 구간이 끝나면 기본 5초간 수신을 기다립니다. 이어서 남아 있는 연결을 고정하고 검증 메시지 3개를 보내며, 다시 5초간 수신을 기다려 누락·중복을 확인합니다. 이때 검증 메시지도 DB에 저장됩니다.

**누락·중복률은 마지막 고정 구성 검증 구간에만 적용됩니다.** 무작위 구간 전체의 전달을 보장하지 않습니다. 1명 테스트나 검증 구간에 수신자가 없으면 해당 지표는 '측정 불가'입니다. 미수신은 대기 종료 시점까지 도착하지 않은 전달이며 영구적인 패킷 손실이라고 단정하지 않습니다.

## 지표의 정의

| 지표 | 측정 범위 |
| --- | --- |
| 동시 접속 수 | 입장 응답을 받은 연결의 현재·최대 개수, 서버 측은 별도 1초 표본 |
| 접속 성공률·실패율 | 초기 접속 및 재접속 시도 전체 기준 |
| 접속 시간 | TCP 연결 시작부터 입장 응답까지, 성공한 시도의 평균/p50/p95/p99 |
| 연결 종료율 | 예기치 않은 연결 종료 / 접속 성공 수, 계획된 퇴장 및 최종 정리는 제외 |
| 송신률 | 부하 구간 성공 송신 / 실제 부하 시간, 마지막 검증 메시지 제외 |
| 중계 처리량 | 부하 구간에 도착한 테스트 채팅 프레임 / 부하 시간, 드레인·검증 수신 제외 |
| 전달 지연 | 같은 테스트 프로세스의 단조 시계로 송신 직전부터 상대 수신까지, 평균/p50/p95/p99 |
| 누락·중복률 | 고정 구성 구간에서 예상 전달 건수 대비 미수신·중복 건수 |
| 서버 CPU | 서버 프로세스의 할당 코어 전체 기준 0~100%, Linux에서는 VM 전체 CPU도 별도 수집 |
| 서버 메모리 | 서버 프로세스 작업 집합, Linux VM 전체는 MemTotal−MemAvailable |
| VM 네트워크 | 활성 비루프백 NIC 전체의 RX/TX, DB·SSH 등 다른 통신 포함 |
| 수신 큐 | 1초 표본의 처리 대기 수, 표본 최대와 마지막 값 |
| DB 시간·실패율 | 연결 풀 대기부터 INSERT 종료까지, 완료 건수와 실패율·평균, 서버 시작 이후 최대 지연 |

p50/p95/p99는 1ms 버킷의 상한이며 10초 초과는 별도 표시합니다. 전달 지연 집계는 부하·드레인·검증에서 관측한 표본을 포함합니다. 테스트 도구 스케줄링 지연도 포함되므로 VM 단독 처리 시간은 아닙니다.

송신 성공은 테스트 PC가 프레임을 썼다는 뜻입니다. 서버의 DB 저장·중계 성공과 다릅니다. 테스트 도구의 송수신 바이트는 완전한 애플리케이션 프레임 기준으로 접속·공지 포함, TCP/IP 헤더·재전송·실패한 부분 송신 제외입니다. VM NIC 수치는 네트워크 계층과 측정 범위가 다르며 OCI 청구 트래픽과 같지 않습니다.

서버 지표는 초기 접속·드레인·검증을 포함한 수집 구간의 1초 표본입니다. 순간적인 CPU·메모리·큐 폭증은 표본 사이에서 놓칠 수 있습니다. DB 평균·실패율은 첫 표본과 마지막 표본의 카운터 차이로 계산하며, 최대 DB 지연은 서버 프로세스 시작 이후 값입니다.

## 서버 지표 수집

서버는 실행 파일 폴더에 server-metrics.json을 1초마다 교체합니다. 비밀번호나 채팅 내용은 기록하지 않으며 공개 측정 포트를 열지 않습니다.

- 로컬: 기본적으로 Sources/TRPG.Server/bin/Debug/net9.0/server-metrics.json을 읽습니다. 출력 경로가 다르면 --server-metrics-file로 지정합니다.
- VM: 기존 Windows OpenSSH와 ubuntu 계정으로 /home/ubuntu/trpg-server/server-metrics.json을 읽습니다. 기본 키는 D:\Docs\us2d-server-main\ssh-key-2026-04-01.key이며 --ssh-key로 변경할 수 있습니다.
- SSH는 BatchMode와 기존 known_hosts 검증을 사용합니다. 새 호스트 확인·암호 입력이 필요하면 먼저 일반 SSH 접속을 직접 완료하세요. 키 내용을 코드나 명령 인자에 넣지 않습니다.
- VM 서버 실행 계정은 배포 폴더에 지표 파일을 쓸 수 있어야 합니다. 파일 기록 오류는 서버 로그에 표시합니다.
- Windows 로컬 서버에서는 프로세스 CPU·메모리는 측정하지만 VM 전체 CPU·메모리 지표는 표시하지 않습니다.
- 부하 전에 지표가 갱신되는 표본 2개를 최대 10초 동안 기다립니다. 준비되지 않으면 부하를 시작하지 않습니다. 샘플 누락·수집 중 서버 재시작·SSH 실패는 불완전 측정으로 표시합니다. 서버 지표가 없거나 DB 실패가 관측되면 종합 결과를 성공으로 표시하지 않습니다.

## 고정 접속 모드

무작위 접속 없이 모든 송신의 누락·중복을 검사할 때 사용합니다. --rate는 각 사용자가 아니라 방 전체의 초당 메시지 수입니다. --chars는 한글 수이며 추적 식별자가 추가되므로 무작위 모드의 8~16B 조건과 다릅니다.

```powershell
dotnet run --project "D:\Devs\TRPG.Server\Sources\TRPG.Test\TRPG.Test.csproj" -c Debug -- --mode fixed --clients 10 --seconds 30 --rate 1
```

--rate 0은 채팅을 보내지 않는 접속 유지 테스트입니다. --clients 2 --seconds 1860 --rate 0으로 30분 비활성 퇴장을 확인할 수 있습니다. 이 경우 의도한 서버 퇴장이지만 도구는 예기치 않은 종료로 집계합니다. 인원 선택 범위가 999까지이므로 서버 정원 초과 거절 테스트는 이 도구의 현 옵션으로 수행하지 않습니다.

## 판정과 주의점

접속 실패·예기치 않은 종료·송신 오류·고정 구성 누락/중복이 있으면 클라이언트 검사 실패입니다. 서버 지표 수집 불완전 또는 관측 구간 DB 저장 실패도 종합 실패(종료 코드 1)입니다. 잘못된 옵션은 2, 관측 오류 없이 완료하면 0입니다. 성능 목표나 1,000명 수용 능력을 자동 인증하는 판정은 아닙니다.

현재 서버는 DB에 한 건씩 저장한 후 중계합니다. 이 부하를 처리하지 못하면 서버 수신 큐와 전달 지연이 계속 증가할 수 있습니다. 테스트 종료 후에도 처리 대기가 남는지 확인하세요. Ctrl+C로 중단하면 연결과 SSH 수집 프로세스를 정리하고 부분 결과를 출력합니다. 실제 서비스 이용자에게 테스트 채팅이 전달되므로 운영 중인 방에 부하를 줄 때 유의하세요.
